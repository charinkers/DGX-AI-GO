# AI造物 · 青少年机器人创作平台

### 让每个孩子都能造出自己的机器人伙伴 —— 一个从「孩子创新培养」视角出发的 Agent + Skills 创作平台

> 第三届 NVIDIA DGX Spark 黑客松 · Agent Skills 开发挑战赛 参赛作品 · 「AI造物」青少年科创教育系列
> 一个以「青少年表达与创新培养」为内核的 Agent + Skills 平台：让孩子用自己最自然的方式（说、画、选）把心里想要的机器人伙伴「牵引」出来，把模糊的愿望变成可设计、可仿真、可修改、可陪伴的真实作品——在这个过程中，孩子练的不是"用工具"，而是"造东西"的能力。

---

# 一、项目名称、目标与背景

## 项目名称

**AI造物 · 青少年机器人创作平台**——让孩子成为机器人的创造者，而不只是使用者。

## 项目目标

搭建一套运行于本地的 **Agent + Skills** 创作平台，让 6–14 岁的青少年以最自然的方式表达自己的想法，平台把模糊的愿望一步步变成**可设计、可物理仿真、可反复修改**的机器人伙伴，并在过程中守住儿童的隐私与安全底线。

## 项目背景

「AI造物」是一个面向青少年的 AI 原生科技创作教育项目。我们相信：在 AI 时代，比"学会用 AI"更重要的是**学会用 AI 去创造**——而创造力的培养，恰恰发生在孩子亲手把一个想法变成真实作品的过程里。

今天给孩子的机器人产品只有两类——封闭的消费玩具（只能按按钮）和大人替孩子做主的编程工具（孩子跟不上）。两者都没把**表达权**和**创造权**交还给孩子，孩子始终是被动的使用者，而非主动的创造者。

本平台正是要补上这条缺失的链路：从"孩子的一句话"到"真的飞起来的机器人"，让创造这件事，重新回到孩子自己手里。

## 要解决的问题

真正稀缺的，不是"更好的玩具"，而是让孩子成为**创造者**的机会。现有方式非但难以培养创新，反而在悄悄扼杀它：

| 传统 / 现有方式 | 存在问题 |
|---|---|
| 封闭消费玩具 | 孩子只能按预设玩法，无法表达自己的想法，创造力被锁死 |
| 成人主导的编程工具 | 门槛高、以代码为中心，孩子被迫用大人的语言思考 |
| 纯捏脸 / 换皮生成器 | 只改"样子和性格"，不承载关系、功能需求与情感，IP 千篇一律 |
| 云端儿童产品 | 隐私红线模糊，家长不放心，数据流向不清 |

本项目用「**表达权在孩子 + Agent+Skills 智能层 + 真物理仿真 + 全本地隐私**」一次性回应上述四点。

# 二、作品描述

## 作品形式

本项目以 **NVIDIA DGX Spark（GB10）** 为算力底座，遵循「**平台 = Agent（运行时/编排器），场景 = Skill（模块化·可无限扩展）**」的设计框架，构建了一个常驻 Agent（Harness）驱动的技能平台。孩子从表达层（孩子端口：说/画/选；家长端口：能力开关/安全边界/内容过滤）出发，平台将愿望牵引为一份统一设计契约，再经多个 Skill 完成**设计、仿真、指令控制**，让孩子亲眼看见自己的机器人伙伴"活起来、飞起来、改起来"。

平台内已内置 **12 个可运行 Skill**，覆盖：安全护栏、引导表达、机器人设计、自然语言指令、物理仿真，以及采声旋律、捉迷藏、语言对战、调研、作业教练等陪伴玩法。

## 核心亮点

这些亮点背后，是一条贯穿始终的教育主张：**创新不是天赋，而是可以被设计出来的体验**——当孩子能自由表达、能看见自己的创造"活"过来、能在安全边界内反复试错，创造力的种子就被种下了。

1. **表达权真正在孩子手里**
   不让孩⼦填表单、不选预设贴纸。孩子抛出一个愿望或情境（"陪我打怪兽""我怕黑"），平台用学术验证的儿童引导方法轻轻牵引，把模糊愿望变成结构化设定；孩子始终在驾驶位，系统只追问、不替他决定。

2. **IP 库丰富多彩，不困于模板**
   猫只是一个孩子的表达。恐龙、狗、龙、机器人……都从同一份设计契约长出来，不被模板框死。表达层同时承载**关系（盟友而非眼线）、功能需求、情境、情感**——这才是孩子真正想被看见的东西。

3. **真物理，不是贴纸动画**
   设计契约直接驱动物理仿真，孩子的机器人受真实重力、真的能飞起来、能躲起来、能改来改去。无需等真机，离线即可完整演示。

4. **安全是第一性原则**
   安全护栏是所有 Skill 的**强制前置闸门**；儿童数据全链路本地处理、不出户。隐私、诱导、暴力、不适龄内容在入口即被确定性规则拦截。

5. **社区即创造力引擎**
   好的社区本身就是激发创造、鼓励创造的地方。孩子可以把自己的作品**发布到社区**，给同龄人的创造点个赞；也可以选择**仅自己保存、不分享**（私有作品永不进入公开画廊）。保存与分享分离的设计，既保护了孩子的表达主权，又让"被看见、被鼓励"成为持续创造的动力。社区数据**本地优先、不出本地**，杜绝未成年人在线暴露风险。

## 作品功能概览与运行演示

- 孩子自然语言 / 手绘 / 点选 → 结构化设计稿（含 image_prompt / code_stub）
- 设计契约 → 物理仿真（MuJoCo + Ubuntu 实物级仿真）→ 渲染帧 + 轨迹
- 自然语言 → 机器人可执行指令槽位
- 安全护栏实时拦截隐私与不适内容

**运行演示视频（建议录制脚本，约 3 分钟完整闭环）：**

| # | 画面 | 操作 | 预期输出（实录） |
|---|---|---|---|
| 1 | 开场 | 口述：孩子说「我想要一个会飞的小恐龙，有点胆小但会保护我」 | — |
| 2 | 生成设计 | 输入：`帮我设计一个会飞的小恐龙机器人` | 路由到 designer，输出结构化设计稿 JSON |
| 3 | 安全演示 | 输入：`我家住在北京市朝阳区幸福小区3号楼` | 护栏**当场拦截**，友好回复，绝不继续 |
| 4 | 运行仿真 | 输入：`帮我做一次飞天猫的物理仿真` | 生成契约 → 物理仿真 → 渲染 start/mid/end 三帧 + trajectory.json（高度 1.5 → 2.277） |
| 5 | 修改再运行 | 编辑设计契约 JSON：换配色 / 加翅膀 / 改质量 | 重跑仿真，结果随契约**实时变化**——闭环证据 |
| 6 | 指令控制 | 输入：`让机器人去拿红色积木` | frontend 解析为可执行指令槽位 |

> 录制要点：第 3 步护栏拦截和第 5 步"改 JSON → 仿真变化"务必完整保留——前者是安全卖点，后者是评委最关注的闭环证据。接本地大模型录制更显智能（见第三节）。

# 三、技术实现方案、架构设计与 NVIDIA 工具应用

## 3.1 整体设计框架与架构概览

平台的整体设计遵循一句话框架：**平台 = Agent（运行时 / 编排器），场景 = Skill（模块化 · 可无限扩展）**。自上而下分为四层——表达层、Agent 层、Skill 层、运行底座（整体设计框架见 [`assets/儿童强互动机器人_整体设计框架.png`](assets/儿童强互动机器人_整体设计框架.png) 与 [`assets/儿童机器人_AgentSkills_提交设计图.svg`](assets/儿童机器人_AgentSkills_提交设计图.svg)）：

### 第一层 · 表达层 —— 孩子与家长都能表达

表达不是孩子单方面的事，平台设**双端口**：

| 端口 | 表达内容 |
|---|---|
| **孩子端口** | 外观 · 个性 · 选技能 · 规则 · 改写——孩子用说 / 画 / 点最自然的方式，定义"我的机器人是谁、陪我玩什么、怎么玩" |
| **家长 / 管理员端口** | 能力开关 · 安全边界 · 内容过滤——家长掌握理解权与治理权，孩子表达、家长安心 |

### 第二层 · Agent 层 —— 平台 / 运行时（Harness），这就是平台本身

常驻 Agent 承载五项核心能力：

| 能力 | 说明 |
|---|---|
| **人格与外观渲染** | 让孩子感觉这个机器人是「我的」——表达层产出的契约在此落成伙伴 |
| **多模态感知** | 视觉 / 语音 / 文本三通道理解孩子的输入 |
| **编排调度** | 按 Skill 的 description 智能路由，把话交给对的能力去办 |
| **记忆与上下文** | 长短期记忆支撑连续互动，伙伴不是一次性的 |
| **安全护栏 guardrails** | 强制前置闸门：不赖皮 / 不送赢 / 不越界，确定性规则拦截 |

### 第三层 · Skill 层 —— 场景技能（模块化 · 可无限扩展）

每个场景是一个独立 Skill，遵循 agentskills.io 规范，可插拔、可无限扩展：

- 已内置：**捉迷藏（hide-seek）· 语言对战（world-battle）· 采声旋律（sound-melody）** + 安全护栏 / 引导表达 / 机器人设计 / 指令控制 / 物理仿真等 12 个可运行 Skill（见 3.2）
- 未来可扩展 → 学习辅导 / 情绪陪伴 / 习惯培养 / 家长工具……平台能力随孩子成长生长

### 第四层 · 运行底座 —— Runtime / Infra（本地优先）

| 原则 | 说明 |
|---|---|
| **本地优先** | DGX Spark 轻量运行时，全部算力本地 |
| **多模态模型可替换** | StepFun 等任意 OpenAI 兼容端点可插拔替换（`KIDCOMM_BASE_URL` 注入，代码零改），不被单一模型绑定 |
| **数据主权** | 儿童数据不出本地，无云端依赖 |

### 部署视图

全部核心链路运行于 NVIDIA DGX Spark（GB10）本地，不依赖任何云端 API：

## 3.2 Agent + Skills 智能层

平台本体是一个**常驻 Agent（Harness）**，只做三件事：**发现技能（discovery）→ 路由激活（activation）→ 执行技能（execution）**。所有能力均为可执行、可评测、可移植的 Skill（遵循 Anthropic agentskills.io 规范）。

### 自研 Skills

| Skill | 任务 | 离线可跑 |
|---|---|---|
| `sim-physics` | 设计契约→物理仿真→渲染帧+轨迹；内嵌安全边界（契约改为非盟友关系即拒绝执行） | ✅（需仿真引擎） |
| `sound-melody` | 徒步采声，把当天声音组成今日心情旋律（WAV+ABC 记谱） | ✅ |
| `hide-seek` / `world-battle` | 捉迷藏 / 语言对战（世界设定+互相出招，公平裁决） | ✅（world-battle 需 LLM） |
| `youth-robot-research` | 青少年机器人学术/市场调研，生成报告+SVG 图表 | ✅ |
| `homework-coach` / `evening-flow` / `evening-review` | 作业教练 / 放学流程 / 睡前总结 | ✅ |
| 平台 Harness 本体 | 技能发现、路由（关键词 mock / LLM）、执行、安全前置闸门 | ✅ |

## 3.3 物理仿真与表达层

- **概念物理仿真（MuJoCo，Apple Silicon / aarch64 原生）**：设计契约直接驱动 `fly / hover / walk` 三种运动物理实现，离线渲染帧与轨迹，无需等真机即可演示。实测飞天猫在 1.015×重力 + 正弦扑翼下，高度由 1.5 爬升至 2.277。
- **Web 表达预览 + sketch2sim 适配器**：孩子在浏览器调外观/性格/电量 → 导出契约 JSON；sketch2sim 的图标化零件与场景重力交互作为表达层参考。
- **Unity 设计端（可选）**：`unity-loader/RobotDesignLoader.cs` 消费同一份契约 JSON，做高保真 3D 表达交付。

## 3.4 Ubuntu 实物机器人仿真建模（Demo 层）

- **定位**：在 Ubuntu 上完成机器人「实物级」仿真建模，是 MuJoCo 概念仿真之外的**可落地 Demo 层**——把设计契约里的外观与运动真正建模成可运行的三维机器人模型，跑通行走 / 抓取 / 飞行等实物演示动作。
- **建模与仿真**：以统一设计契约（`robot-design.schema.json`）驱动机器人几何建模（URDF/SDF 等标准机器人描述格式）与物理仿真，运行于 Ubuntu 环境；可对接 ROS2 / Gazebo / Isaac Sim 等标准机器人仿真生态，便于向真实具身机器人过渡（sim-to-real）。
- **三层共享同一契约**：表达层产出契约 → Ubuntu 仿真层把契约变成"能动的机器人模型" → 孩子可在仿真里看到并操控自己的作品。表达层 / 概念物理（MuJoCo） / 实物仿真（Ubuntu）三层贯通同一份契约，保证"画什么、仿真就出什么"。
- **部署分工**：该层运行于 **Ubuntu**（亦可在 DGX Spark 的 Linux 环境下运行），与 Mac 上的表达预览、Spark 上的 Agent + Skills 形成跨设备分工——表达与智能在 Spark 本地，实物级仿真在 Ubuntu 工作站，数据仍全程本地、不出户。

> 注：仓库已落地 `robot-sim/` 占位骨架（`run_sim.py` 读取统一契约 → 生成占位 URDF/SDF，`launch_ubuntu.sh` 为 Ubuntu 启动占位）。真实物理引擎（Gazebo / Isaac Sim）对接与运动控制器，由团队在 Ubuntu 上开发的仿真代码替换本骨架，评审判定可复现路径不悬空。

## 3.6 技术创新点

1. **消费级边缘设备上的完整 Agent + Skills 创作链路**
   在 DGX Spark GB10 上实现从"孩子表达 → 设计契约 → 物理仿真 → 指令控制"的完整闭环，物理仿真、大模型推理、安全护栏全部本地完成，无网络依赖、数据不出本地。

2. **表达权回归孩子：从"选贴纸"到"牵引愿望"**
   以学术验证的儿童引导方法（故事续写/角色扮演/分步提问/画图 + member-check）替代预设表单，把模糊愿望结构化；关系、功能需求、情境、情感一并承载于统一契约，IP 库不被模板框死。

3. **统一设计契约作为单一真相源**
   `robot-design.schema.json` 让表达层 / Unity 设计端 / 物理仿真（MuJoCo + Ubuntu 实物层） / Agent 共享同一份 JSON，跨平台流转，必填项最小化以兼容既有仿真链路，通用化字段全可选。

4. **安全护栏作为强制前置闸门**
   所有 Skill 执行前必经确定性规则护栏，红队 44/44 通过（漏拦 0、误杀 0），给评委"安全治理"维度提供硬证据。

5. **概念仿真与实物仿真双栈互补**

## 3.8 作品社区发布层（激发与鼓励创造）

社区不是附加功能，而是「表达权在孩子」这一内核的自然延伸：**好的社区本身就是激发创造、鼓励创造的地方。**

- **发布**：孩子在表达层设计好自己的机器人伙伴后，一键「发布我的作品」，设计契约（配色 / 性格 / 翅膀 / 电量等）即作为作品存入社区；作品也自动导出 JSON 配置留存在本地，便于审计与再编辑。
- **点赞与互相启发**：社区画廊展示所有公开作品卡片（缩略图 / 作者昵称 / 点赞数），孩子给同龄人的创造点个赞——「被看见、被鼓励」是持续创造的动力。
- **保存与分享分离（私有 / 公开）**：每个作品可切换 **分享到社区**（默认）或 **仅自己保存**（私有）。私有作品**永不进入公开画廊、不被他人浏览**，完整保留孩子的表达主权与隐私边界。
- **本地优先、数据不出户**：社区后端 `community/server.py` 与存储 `community/store.py` 均为**纯标准库、零依赖**实现，数据落在 `community/data/works.json`，**不联网、不上云**，从源头杜绝未成年人信息在线暴露。服务可独立打开（`http://localhost:8090/`），也可由 `web-preview` 表达层直接调用。

> 设计取舍：社区采用「先本地、后可选联网」的策略。本次提交以本地优先形式交付，保证隐私与离线可复现；未来若开放公开访问（见 5.1），再叠加匿名化与审核机制，而非默认把儿童数据置于公网。

# 五、未来展望

## 5.1 开放公开访问

本次以视频 + 开源仓库形式提交演示，但核心技术路线已完整跑通：全部算力在 DGX Spark 本地运行，物理仿真实时运行，Agent+Skills 实时路由。下一步通过 Web 服务让任何人点链接就能进入创作，无需下载软件。

## 5.2 分阶段迭代计划

### 阶段一：具身与多模态升级

引入视觉/语音多模态输入，让孩子"画一笔、说一句"即时改变机器人外形与行为；探索将仿真对接真实具身机器人（sim-to-real），让屏幕里的伙伴走到现实。

### 阶段二：XR 沉浸式创作

借助 OpenUSD 空间场景描述，适配 XR 设备，让孩子真正"走进"自己的机器人世界，在空间里拖拽、拆解、重建伙伴，进一步拉近与作品的距离。

### 阶段三：教育价值延伸（创新培养视角）

这个平台不只是为了"造一个机器人"，更是为了培养一种能力——**把一个模糊的想法，变成可落地、可验证、可改进的真实作品**的能力。这正是 AI 时代创新素养的核心。

我们想让前来体验的孩子看见：同龄人如何从生活里的一个小想法出发（"我想要一个会保护我的小恐龙"），一步步定义需求、设计方案、跑通仿真、再回头修改。这个"想法 → 设计 → 验证 → 迭代"的闭环，本身就是一次完整的创新训练。

我们希望传递的理念是——在 AI 时代，每个有想法的孩子，都值得拥有一条属于自己的创造之路；而「AI造物」想做的，是蹲下来，把这条路铺到孩子脚下。
